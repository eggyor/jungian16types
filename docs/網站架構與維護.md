# 網站架構與維護

## 網站如何運作

網站以 Jekyll 將 Markdown 文章、Liquid 範本和靜態頁面組合成 HTML。正式部署由 GitHub Actions 執行 `.github/workflows/pages.yml`：取得程式碼、執行 Instagram 同步（有提供 Secret 時）、計算文章推薦、建置 Jekyll、部署 GitHub Pages。工作流程在 `main` 更新、手動觸發及每日 UTC 10:17 執行；每日排程主要用來更新 Instagram（香港時間約 18:17）。

網站設定在 `_config.yml`，目前網址為 `https://jungian16types.com`、`baseurl` 為空。GitHub Pages 發佈來源應使用 GitHub Actions。Liquid 樣板須經 Jekyll 建置，不能直接用瀏覽器開啟原始檔來預覽。

## 重要檔案與目錄

| 路徑 | 用途 |
|---|---|
| `index.html` | 首頁、首頁介紹及社群／Instagram 內容 |

| `_includes/site-theme-links.html` | 載入共用主題、元件、夜間模式樣式與主題切換程式 |
| `_layouts/post.html` | 文章頁版型、分享區、標籤、SEO 中繼資料與文章結構化資料 |
| `_posts/` | Jekyll 文章來源 |
| `templates/文章範本.md` | 新文章的起始範本 |
| `theory/index.html`、`theory/<分類>/index.html`、`_includes/theory-page.html` | 理論文章總目錄與七個易讀分類網址，共用同一頁面內容；人物分析文章列表會動態讀取文章資料 |
| `tags/index.html`、`tags/<標籤>/index.html`、`_includes/person-analysis-tag-page.html` | 標籤索引、各標籤文章頁，以及人物分析標籤預覽頁 |
| `_data/person_analysis_tags.yml` | 人物分析專用的八種標籤名稱與顯示順序 |
| `quiz/`、`quiz/start/`、`quiz/results/` | 測驗入口、作答頁與易讀結果網址；舊編號網址保留轉址 |
| `/alchemy/` | 煉金工房 |
| `assets/css/` | 共用視覺、夜間模式、首頁、測驗與結果頁樣式 |
| `assets/js/` | 主題切換、測驗、文章連結預覽等互動程式 |
| `assets/images/`、`img/` | 網站圖片和舊站媒體資產；新增文章圖檔優先放 `assets/images/` |
| `_data/` | Jekyll 使用的資料檔，例如測驗對照、Instagram 貼文及建置產生的相關文章資料 |
| `scripts/` | 建置前執行的相關文章計算和 Instagram 同步程式 |
| `.github/workflows/pages.yml` | 自動建置與部署流程 |

## 共用頁首、頁尾與主題

頁首和頁尾由 `_includes/header.html`、`_includes/footer.html` 共用；版面樣式主要在 `assets/css/site-chrome.css` 和 `assets/css/site-theme.css`。理論文章的七個分類位於 `theory/index.html` 同一頁，分類切換不會載入另一個 HTML 頁。人物分析標籤頁由 `tags/<標籤>/index.html` 引入共用樣板，不需為每個標籤複製列表邏輯。不要復原已淘汰的獨立理論分類頁或舊分類封面縮圖。

全站日夜模式由 `assets/js/theme-mode.js` 切換，選擇保存於瀏覽器 `localStorage`。共用基礎色彩在 `assets/css/site-theme.css`，夜間覆寫在 `assets/css/night-mode.css`；新增元件時應同時確認白天和夜間的文字、背景、按鈕、邊框及焦點狀態。各頁或舊結果頁仍可能有自己的內嵌樣式，若夜間外觀不一致，需檢查其選擇器與載入順序。

## SEO 與圖示

文章頁的 canonical、Open Graph／社群分享資料及 Article 結構化資料由 `_layouts/post.html` 與 `_includes/seo-canonical.html` 輸出。網站圖示包含根目錄的 `favicon.png` 和 `apple-touch-icon.png`；改 logo 或網站名稱時，記得檢查瀏覽器分頁圖示及分享預覽。

## 維護原則

- 保留 Jekyll 所需的目錄和檔名；中文路徑使用 UTF-8。
- 修改共用元件時，確認首頁、一般頁、文章頁、測驗結果頁和理論分類頁都仍適用。
- 涉及文章分類或標籤時沿用詞彙表中的精確名稱，避免同義異寫導致列表分裂。
- 文章推薦 JSON 由 `scripts/build_related.py` 產生，不要手動維護 `_data/related_posts.json`。
- Instagram 資料及縮圖由同步腳本更新；不要將 access token 寫入前端或提交到版本庫。
- 聯絡表單的 Turnstile secret 和 Resend API key 只放在 Cloudflare Worker Secrets。
- 以 GitHub Actions 的建置／部署結果確認線上版本；靜態 HTML 原始檔不是 Liquid 頁面的成品預覽。
